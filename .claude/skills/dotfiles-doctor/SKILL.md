# dotfiles doctor

**진단 먼저, 고치는 건 분류 후.** 사실 오류는 바로 고치고, 판단이 갈리는 것만 모아 한 번에 묻는다.

## 1. 기계적 점검

```bash
bash ~/.dotfiles/.claude/skills/dotfiles-doctor/scripts/doctor.sh
```

읽기 전용이다. `[FAIL]` 은 고칠 목록에 바로 넣고, `[WARN]` 은 하나씩 확인해 오탐이면 버린다. `[INFO]` 의 버전 기준은 2단계 재료다.

## 2. claude/ 하네스 점검

`claude/` 아래 파일을 **전부** 읽는다 (한 메시지에 병렬로). 아래 기준으로 대조한다.

| 점검 | 대조 대상 |
|---|---|
| 문서가 쓰라는 도구·파라미터가 실제로 있는가 | 현재 세션의 도구 목록, `claude --version` |
| 규칙끼리, 규칙과 실제 설정이 맞는가 | `settings.json`, `zsh/zshrc` alias, `Makefile`, 훅 스크립트 |
| 요약 숫자·참조가 실제와 맞는가 | 단계 수, 규칙 번호, `§N` 참조, 파일 목록 |
| 지킬 수 없거나 다른 규칙과 부딪히는 지시 | 특히 「출력 길이」「핵심 원칙」 |
| 동작 설명이 사실인가 | 직접 확인 가능한 것만. 확인 못 하면 **"미확인"으로 보고하고 고치지 않는다** |
| 비어 있거나 쓰지 않는 파일·설정 | `enabledPlugins`, 빈 설정 파일, 끝난 이관 메모 |
| 최신 모델에 과한 지시 | 기계적 게이트, 시키지 않아도 하는 일을 시키는 지시 — **판단 항목** |

## 3. 분류하고 한 번에 묻기

- **사실 오류** (없는 도구, 틀린 숫자, 끊긴 참조, 지운 대상): 질문 없이 고칠 목록에 넣고, 질문 메시지에 한 줄씩 밝힌다
- **판단 항목** (조건 변경, 삭제, 문서와 실제 중 어느 쪽에 맞출지): `~/.claude/docs/workflow.md` §7 대로 `AskUserQuestion` 으로 한 번에 묻는다. 선택지마다 근거 (어느 파일의 어느 내용) 와 추천안을 붙인다

## 4. 적용

- 하나를 지우거나 바꾸면 **연쇄 참조를 같이 고친다**: `Makefile` 링크 목록, `docs/structure.md`, `docs/architecture.md`, `docs/setup.md`, 훅 스크립트의 안내문
- `~/` 쪽은 dotfiles 가 만든 링크만 지운다. 링크가 아닌 실파일 (머신별 파일) 은 건드리지 않고 보고만 한다

## 5. 검증

1. `doctor.sh` 재실행 — FAIL 0
2. `make sync` 두 번 — 둘 다 exit 0 (멱등성)
3. 고친 훅 스크립트는 가짜 입력 JSON 으로 실행해 동작 확인
4. 지우거나 이름을 바꾼 것은 `rg` 로 남은 참조가 없는지 확인

## 6. 보고

모순 / 버전 어긋남 / 불필요 로 묶어 무엇을 고쳤는지 보고하고, **건드리지 않은 것과 미확인** 을 따로 적는다. 커밋·push 는 승인을 받은 뒤 한다.

## 점검 축 늘리기

첫 버전은 claude/ 와 공통 점검만 다룬다. 다른 디렉토리 (`brew/`, `zsh/` 등) 의 점검이 필요해지면:
기계적으로 판정되는 것은 `doctor.sh` 에 절을 추가하고, 판단이 필요한 것은 2단계 표 아래에 디렉토리별 표를 추가한다.
