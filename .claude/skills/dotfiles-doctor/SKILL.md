# dotfiles doctor

**진단 → 처방서 → R1 (처방서 리뷰) → 적용 → R2~ (diff 리뷰, 수렴할 때까지) → 커밋·push → 보고.** 처음부터 끝까지 사용자에게 묻지 않고 진행한다 (2026-10-09 사용자 결정).

이 스킬 안에서는 전역 규칙 중 아래를 이 문서의 절차로 대체한다.
- `~/.claude/docs/workflow.md` §7 (착수 전 질문) → 아래 「진행 중 묻지 않는다」
- workflow §1·§2 (계획 모드, 계획서 적대적 검증) → 처방서와 검증 루프. 계획 모드로 들어가지 않는다
- 규칙 3 의 `qa-runner` 위임 → 검증 명령은 몇 번의 호출로 끝나므로 직접 돌린다 (workflow §3-3)

## 진행 중 묻지 않는다 — 판단은 스스로, 예외는 마지막에

- 판단 항목은 **추천안을 직접 고르고** 처방서에 근거를 남긴다. 근거가 약하면 덜 바꾸는 쪽을 고른다
- 아래는 자동 적용하지 않고 `마지막에 질문` 으로 분류한다. 나머지 작업은 이것과 무관하게 끝까지 진행한다
  - 사용자 지시·지적·결정으로 들어간 규칙을 뒤집거나 지우는 것 — 문서에 `(YYYY-MM-DD 사용자 지시)` · `사용자 지적` · `사용자 결정` 같은 표기가 붙은 규칙
  - 표기가 없어도, **직전 `doctor:` 커밋 이후 doctor 가 아닌 커밋** (사람이 만든 변경) 이 바꾸거나 지운 내용을 되돌리거나 되살리는 것 — 추천안을 고르기 전에 대상 줄의 이력 (`git log -L` · `git log -S`) 을 확인한다. `doctor:` 커밋이 만든 변경은 자유롭게 고친다. `doctor:` 커밋이 아직 없으면 표기만 본다
  - 시작 시점에 미커밋 변경이 있던 파일을 건드리는 것 (사람이 아직 커밋하지 않은 작업을 덮어쓰지 않게)
  - 저장소 밖 실파일 (링크가 아닌 머신별 파일) 을 지우거나 고치는 것
  - 사용자만 할 수 있는 일 (로그인·권한·외부 확인)

## 1. 진단 (병렬)

한 메시지에 묶어 동시에 돌린다.

- 기계적 점검: `bash ~/.dotfiles/.claude/skills/dotfiles-doctor/scripts/doctor.sh` (읽기 전용). `[FAIL]` 은 항목으로, `[WARN]` 은 확인해 오탐이면 버린다, `[INFO]` 는 범위·버전 판단 재료
- 시작 시점의 `git status --porcelain` 과 `git rev-list --count @{u}..HEAD` (upstream 보다 앞선 커밋 수) 를 기록한다. **미커밋 변경이 있거나 앞선 커밋이 있으면 이번 실행은 자동 커밋·push 하지 않는다** (6단계) — 검증한 작업 트리와 커밋 내용이 달라지거나, 리뷰하지 않은 커밋이 같이 push 되므로. upstream 이 없으면 앞선 커밋은 보지 않고, 6단계에서 커밋만 하고 push 하지 않는다
- `claude/` 아래 파일 **전부** 읽기, 다른 디렉토리는 아래 공통 점검 기준에 필요한 파일 읽기 (Read 병렬)
- `doctor.sh` 「저장소 구성」 결과로 범위를 정한다: 마지막 doctor 실행 이후 바뀐 최상위 항목을 먼저·깊게 보고, 나머지도 빠뜨리지 않는다
- 동작 설명이 사실인지 실제로 띄워 봐야 알 수 있으면 시험용 서브에이전트를 병렬로 띄워 확인한다. 팀 동작 자체를 시험할 때만 팀메이트 (`name`) 를 쓰고, 그때는 `~/.claude/docs/team-mode.md` 를 먼저 읽고 확인 즉시 `TaskStop` 으로 해산한다

### claude/ 하네스 점검 기준

| 점검 | 대조 대상 |
|---|---|
| 문서가 쓰라는 도구·파라미터가 실제로 있는가 | 현재 세션의 도구 목록·스키마, `claude --version` |
| 규칙끼리, 규칙과 실제 설정이 맞는가 | `settings.json`, `zsh/zshrc` alias, `Makefile`, 훅 스크립트 |
| 요약 숫자·참조가 실제와 맞는가 | 단계 수, 규칙 번호, `§N` 참조, 파일 목록 |
| 지킬 수 없거나 다른 규칙과 부딪히는 지시 | 특히 「출력 길이」「핵심 원칙」 |
| 동작 설명이 사실인가 | 직접 확인 (필요하면 시험용 에이전트). 끝내 확인 못 하면 "미확인" 으로 보고하고 고치지 않는다 |
| 비어 있거나 쓰지 않는 파일·설정, 발동하지 않는 훅 | `enabledPlugins`, 빈 설정 파일, 끝난 이관 메모, 훅이 판정에 쓰는 필드가 실제로 기록되는지 |
| 최신 모델에 과한 지시 | 기계적 게이트, 시키지 않아도 하는 일을 시키는 지시 |

### 모든 디렉토리 공통 점검 기준

전용 표가 없는 디렉토리 (새로 생긴 것 포함) 는 이 기준으로 본다. 역할은 `docs/structure.md` 「디렉토리 개요」 표에서 읽는다. 표에 없는 디렉토리는 `doctor.sh` 가 WARN 으로 올리므로, 표에 역할을 추가하는 항목을 만들고 이 기준으로 본다 — 이 스킬은 고칠 필요가 없다.

| 점검 | 대조 대상 |
|---|---|
| 내용이 표에 적힌 역할과 맞는가 | `docs/structure.md` 의 해당 행 |
| 아무도 쓰지 않는 파일 (하위 디렉토리 포함) | `Makefile`, 다른 스크립트·설정에서 파일명으로 `rg` |
| 설정이 가리키는 명령·경로·앱이 이 장비에 있는가 | `command -v`, 경로 존재 확인 |
| 같은 일을 하는 설정이 다른 디렉토리에도 있는가 | 다른 디렉토리의 같은 종류 설정 |

감지 한계: `doctor.sh` 는 **최상위** 디렉토리·파일만 표·안내 문서와 대조한다. 하위 디렉토리에 새로 생긴 모듈은 위 「아무도 쓰지 않는 파일」 점검이 잡는다. `.gitignore` 된 디렉토리는 저장소 구성이 아니므로 보지 않는다. 최상위 파일 이름이 문서에 일반 단어로 나오면 (예: `brew`) 언급된 것으로 본다.

## 2. 처방서

`.prompts/doctor-<YYYYMMDD-HHMM>.md` (gitignore 됨) 에 쓴다. 리뷰어에게는 이 경로를 넘긴다.

```markdown
# doctor 처방서 <YYYY-MM-DD HH:MM> · Claude Code <버전>

## 항목
| # | 분류 | 대상 파일 (연쇄 참조 포함) | 바꿀 내용 | 근거 (파일:줄 · 명령 결과 · 시험 결과) | 처리 |
<!-- 분류: 사실 오류 / 판단 (고른 추천안과 이유) · 처리: 자동 적용 / 마지막에 질문 / 보고만 (미확인) -->

## 검증 라운드
- R1: 지적 → 조치 (반영 / 기각 + 사유 ①②③)
```

- 연쇄 참조는 같은 항목에 묶는다: `Makefile` 링크 목록, `docs/structure.md`, `docs/architecture.md`, `docs/setup.md`, 훅 스크립트의 안내문, `settings.json`
- `~/` 의 링크를 지우는 항목은 처방서에 지울 링크와 그 `readlink` 값을 적어 두고, 항목을 적용할 때 (4단계 또는 R2~ 반영) 파일과 같이 지운다. 링크는 git 밖이라 커밋 조건과 무관하다. 항목을 되돌리면 적어 둔 값으로 `ln -s` 해 되살린다 (`make sync` 는 매핑에서 빠진 링크를 되살리지 못한다)

## 3. 적대적 검증 루프 (최소 2라운드 · 최대 9라운드 — 2026-10-09 사용자 결정)

| 라운드 | 리뷰 대상 | 끝나면 |
|---|---|---|
| R1 | 처방서 | 반영 후 4단계 (적용) → 5단계 (기계적 검증) |
| R2 ~ R9 | 처방서 + `git diff HEAD` + 직전 5단계 결과 | 지적을 처방서와 작업 트리 (`~/` 링크 포함, 4단계 규칙대로) 에 같이 반영 → 5단계 |

**리뷰어**: 매 라운드 새로 띄운다 (`subagent_type: general-purpose`). 앞 라운드 리뷰어를 이어 쓰지 않는다 — 앞선 결론에 끌려가지 않게. 아래에 해당하면 **2명을 한 메시지에 병렬로** 띄워 두 관점을 나눠 맡기고, 아니면 **1명** 이 두 관점을 모두 답한다.
- R1: 처방서에 `판단` 항목이 있다
- R2~: 변경 파일이 3개 이상이거나 `Makefile` · 훅 스크립트 · `settings.json` 을 건드렸다

| 관점 | 답하게 할 것 |
|---|---|
| 사실·근거 | 근거가 주장을 실제로 뒷받침하는가 (직접 열어 확인) · 진단이 놓친 항목 · "미확인" 인데 사실로 적은 것 · (R2~) diff 가 처방서와 일치하는가 |
| 회귀·과잉 변경 | 적용하면 깨지는 것 (`make sync`, 훅, 참조) · 빠진 연쇄 참조 · 새로 생긴 규칙 간 모순 · 더 적게 바꾸는 대안 · `마지막에 질문` 이어야 할 것을 `자동 적용` 으로 분류한 것 |

리뷰어에게 넘길 것: 처방서 경로, "dotfiles 를 진단·정리한다" 는 목적, 대상 파일 경로, (R2~) `git diff HEAD` 와 5단계 결과, 역할 **"승인하지 말고 반박하라"**, **"파일 수정·`make sync` 실행 금지 (읽기 전용)"**. 모든 지적에 근거 (파일:줄 · 명령 결과) 와 등급 (`BLOCKER` 진행 불가 / `MINOR` 보완 권고) 을 붙이게 한다. 「검증 라운드」 의 앞선 기각은 반박할 수 있게 하되, 새 근거 없이 되풀이하는 것은 지적으로 세지 않는다.

R2~ 의 diff 는 넘기기 직전에 만든다: 새로 만든 파일은 먼저 `git add -N` 으로 diff 에 보이게 하고, 그 `git diff HEAD` (스테이징된 변경까지 보이게) 를 `.prompts/doctor-<…>.diff` 로 저장해 리뷰어에게 넘긴다 (6단계에서 커밋 직전 diff 와 대조 — 리뷰어에게 넘긴 것만 저장한다).

**지적 처리** — 반영하거나, 아래 사유 중 하나로만 기각하고 「검증 라운드」 에 남긴다.
- ① 근거가 틀림 — 반증 (명령 결과·파일 내용) 첨부. `BLOCKER` 는 이 사유로만 기각할 수 있다
- ② 처방서·doctor 범위 밖 — 다음 실행 몫이거나 doctor 가 검증할 수 없는 것. 보고에 남긴다
- ③ 효과에 비해 변경이 큼 — 덜 바꾸는 원칙

**종료** (2026-10-09 사용자 결정): R2 이상에서 **`BLOCKER` 0건인 라운드가 두 번 연속** 나오면 끝낸다. 종료하는 라운드의 `MINOR` 는 반영하지 않고 ② (다음 실행 몫) 로 보고한다 — 그래야 마지막으로 리뷰한 diff 가 커밋할 diff 와 같다. 그 앞 라운드의 `MINOR` 는 평소대로 반영하거나 기각한다. 같은 쟁점이 라운드마다 뒤집히면 (앞 라운드에서 반대로 고친 것을 다시 고치라는 지적) 현상 유지 쪽으로 정리한다 — `MINOR` 는 ③ 으로 기각하고, `BLOCKER` 는 양쪽 근거가 모두 맞는 트레이드오프이므로 그 항목을 `보고만` 으로 내리고 그 항목의 변경만 되돌린다 — 이 되돌림은 **반영으로 센다** (다음 라운드가 되돌림을 리뷰한다). R9 까지 수렴하지 않으면 **자동 커밋하지 않고** 7단계 보고로 넘긴다.

## 4. 일괄 적용 (R1 직후, 병렬)

먼저 처방서에 적은 `~/` 링크를 확인한다: `[ -L ]` 로 링크인지, `readlink` 가 `~/.dotfiles/` 아래를 가리키는지. 실파일이거나 다른 곳을 가리키는 링크 (사용자가 직접 만든 것) 면 그 항목을 `마지막에 질문` 으로 넘기고 이번 적용에서 뺀다 — 파일을 고치기 전에 하므로 되돌릴 것이 없다.

`자동 적용` 항목을 **파일 소유권이 겹치지 않는 묶음** 으로 나눈다 (연쇄 참조는 원래 항목과 같은 묶음).

- `Makefile` · 훅 스크립트 · `settings.json` 을 포함한 묶음은 직접 고친다 (workflow §3-1 — 멱등성·정합성이 걸린 구현)
- 나머지 묶음이 2개 이상이고 각 묶음이 몇 줄짜리 수정보다 크면 `impl-dev` 를 묶음별로 한 메시지에 동시 스폰한다. 프롬프트: 처방서의 해당 항목 전문, 대상 파일 절대경로, "스코프 밖 수정 금지 · 커밋 금지 · `make sync`/`doctor.sh` 실행 금지"
- `impl-dev` 가 멈춰서 돌아오면 (스코프 밖 · 인터페이스 변경) 처방서 범위 안이면 직접 마저 처리하고, 범위를 넘으면 그 항목을 `보고만` 으로 내리고 이미 고친 부분을 되돌린다 (같은 파일의 다른 항목은 남기게 그 부분만. 파일 통째 `git checkout` 금지)
- 그 밖에는 직접 한 번에 고친다
- 이 문서에서 "되돌린다" 는 그 항목이 바꾼 부분만 원래대로 돌리는 것이다. 새로 만든 파일은 인덱스에 있으면 (`git add -N` 이후) `git rm -f <파일>`, 없으면 `rm` 으로 지운다 — 흔적이 남으면 6단계 부분집합 조건에 걸린다. 항목이 기존 파일을 지웠다면 `git checkout HEAD -- <파일>` 로 통째 되살린다 (`git rm` 으로 지운 경우도 된다) (위 「파일 통째 `git checkout` 금지」 의 예외)
- 확인을 통과한 `~/` 링크를 지운다

## 5. 기계적 검증 (적용 후 · 매 라운드 반영 후)

1. `make sync` 두 번 — 둘 다 exit 0 (멱등성)
2. `doctor.sh` 재실행 — 시작 때 없던 **새 FAIL 0**, 그리고 `자동 적용` 항목이 고치기로 한 FAIL 은 사라짐 (`보고만` · `마지막에 질문` 으로 남긴 항목의 FAIL 은 남아도 된다)
3. 고친 훅 스크립트는 가짜 입력 JSON 으로 실행해 동작 확인 (서로 독립이면 병렬)
4. 지우거나 이름을 바꾼 것은 `rg` 로 남은 참조가 없는지 확인
5. 지운 `~/` 링크 목록과 `ls -la` 결과를 남긴다 (git diff 에 보이지 않으므로 다음 라운드 리뷰어에게 같이 넘긴다)

실패는 다음 라운드의 지적과 같이 다룬다. 마지막 라운드 뒤에도 실패하면 **커밋하지 않는다.**

## 6. 커밋·push (자동 — 2026-10-09 사용자 결정)

변경이 0건이면 커밋·push 하지 않는다 (기준점 `doctor:` 커밋도 생기지 않는다 — 다음 실행은 직전 기준점을 그대로 쓴다). 그 밖에는 아래를 **모두** 만족하면 묻지 않고 커밋한다. 하나라도 어기면 커밋하지 않고 7단계로 넘긴다.

- 루프가 수렴했고 (3단계 종료 조건), 마지막 5단계가 통과
- 시작 시점에 미커밋 변경도, upstream 보다 앞선 커밋도 없었다 (1단계)
- 커밋 직전 `git diff HEAD` 가 **마지막 라운드에서 리뷰한 diff** (3단계에서 마지막으로 리뷰어에게 넘기며 저장한 것) 와 같다 — 그 뒤 Claude Code 등이 같은 파일에 끼워 넣은 hunk 를 막는다
- `git status` 의 변경 파일이 모두 **최종 처방서에서 `자동 적용` 인 항목들의 대상 파일 안에 있다** (부분집합 — 연쇄 참조로 적었지만 고칠 필요가 없던 파일은 괜찮다). 목록 밖의 변경 (세션 중 Claude Code 가 고친 `settings.json` 등) 이 있으면 중단

절차:

1. 처방서의 대상 파일만 이름으로 스테이징한다 (`git add -A` 금지)
2. 커밋 메시지는 전역 규칙대로 한국어로 쓰고, 제목은 **`doctor:` 로 시작**한다 (다음 실행이 이 커밋을 기준으로 바뀐 항목을 찾는다). 본문은 분류 (모순 / 버전 어긋남 / 불필요) 별 요약, 사용자 답으로 적용한 항목은 「사용자 결정」 으로 따로 적는다. 본문에 `Claude Code: <x.y.z>` 줄 (`claude --version`) 을 넣는다 — 세션 시작 제안 훅 (`scripts/suggest.sh`) 이 버전 변경을 판정하는 기준이다
3. 브랜치가 detached 가 아니고 upstream 이 있으면, `git rev-list --count @{u}..HEAD` 가 **1 (doctor 커밋뿐)** 인지 확인하고 `git push`. upstream 이 없으면 push 하지 않고 보고한다. 거부 (non-fast-forward) 나 권한 차단이면 우회·강제하지 않고 보고한다

커밋하지 못한 경우 작업 트리는 **되돌리지 않고** 남긴다 (사용자가 diff 를 볼 수 있게). 보고에 "다음 실행 전에 커밋하거나 되돌릴 것 — 되돌릴 땐 4단계의 「되돌린다」 정의대로 (기존 파일 `git checkout HEAD -- <파일>`, 새 파일은 인덱스에 있으면 `git rm -f` 없으면 `rm`) 한 뒤 `make sync`, 지운 `~/` 링크는 처방서에 적은 `readlink` 값으로 `ln -s`" 를 적는다 — 그대로 두면 다음 실행도 시작 시점 미커밋 변경 때문에 자동 커밋하지 못한다.

## 7. 보고

- 첫 줄: 커밋 해시와 push 결과 (또는 커밋하지 않은 이유)
- 모순 / 버전 어긋남 / 불필요 로 묶은 변경 요약, 라운드 수
- **모든 라운드에서 기각한 지적과 사유** (리드의 기각을 사용자가 볼 수 있게), `보고만` 으로 내린 항목과 이유
- 건드리지 않은 것 · 미확인
- `마지막에 질문` 항목이 있으면 `AskUserQuestion` 한 번으로 묻는다 (선택지마다 근거와 추천안).
- 자동 커밋하지 못했으면 이유와 해결 방법만 보고하고 커밋 여부는 묻지 않는다 — 리뷰하지 않은 변경이 `doctor:` 커밋에 섞이므로, 사용자가 diff 를 보고 직접 커밋한다. 그때 제목은 `doctor:` 로 시작하지 않게 안내한다 (직전 `doctor:` 커밋이 있으면, 사용자가 검토해 커밋한 변경은 다음 실행에서 사람이 만든 변경으로 보호된다. 아직 `doctor:` 커밋이 없으면 보호는 표기뿐이므로, 지키고 싶은 규칙 줄에 `(YYYY-MM-DD 사용자 결정)` 을 붙이라고 같이 안내한다)
- 답을 받으면: 질문 항목을 답대로 적용할 때는 바뀐 규칙 줄에 `(YYYY-MM-DD 사용자 결정)` 을 붙인다 (다음 실행이 묻지 않고 되돌리지 않게). 그다음 질문 항목에 대한 답만으로 2단계 처방서를 새로 만들어 3~7단계를 다시 돈다 — 이 처방서의 항목은 답을 받았으므로 `자동 적용` 이다 (다시 `마지막에 질문` 으로 분류하지 않는다) (루프 최소 2라운드 포함). 이 재실행은 작업 트리가 깨끗해진 뒤 시작한다

## 점검 축 늘리기

새 디렉토리는 공통 점검 기준이 자동으로 다룬다. 전용 표는 공통 기준으로 부족할 때만 만든다 — 한 디렉토리에서 공통 기준 밖의 항목이 반복되면 그 디렉토리의 전용 표 추가를 처방서 항목 (판단) 으로 올린다. 기계적으로 판정되는 것은 `doctor.sh` 에 절을 추가한다.
