# 전역 에이전트 규칙 (Claude Code · Codex 공용)

> 도구에 묶이지 않는 공용 규칙만 둔다. Claude Code 전용 규칙 (도구·워크플로우) 은 `claude/CLAUDE.md` 에 있다.
> 연결: `~/.claude/CLAUDE.md` 가 `@AGENTS.md` 로 import, `~/.codex/AGENTS.md` 는 이 파일의 심링크.

## 언어
- 한국어로 응답
- **존댓말로 응답** (해요체/합니다체). 반말/평어체 금지
- Git 커밋 메시지도 한국어로 작성 (커밋 메시지 본문은 간결한 평어체 OK — 설명문 형식이므로)
- 영어와 한국어 혼용 시 **띄어쓰기 추가** (예: "Makefile 에서")

## 용어·설명 (질문·답변·문서 공통)

> 어려운 이유는 단어가 어려워서가 아니라 **이름이 모호하거나 도중에 바뀌기 때문**이다. 이름을 잘 고르면 설명이 줄어 답변도 짧아진다.

- **역할이 드러나는 이름을 쓴다.** `A/B` · `1번/2번` 금지 → `기존 DB / 신규 DB`, `primary / secondary`. 고유명사가 있으면 그대로 쓴다
- **한 대상 = 한 이름.** 도중에 `B`·`새 쪽`·`타깃` 으로 갈아타지 않는다. **사용자가 쓴 이름이 있으면 그 이름에 맞춘다**
- **범용 동사는 목적어와 함께.** "전환합니다" ✗ → "쓰기 대상을 기존 DB → 신규 DB 로 전환합니다" ✓ (처리·반영·적용·변경도 동일)
- 대상이 2개 이상이면 **본문 시작 전에 이름표를 한 줄로 선언**하고, 이후엔 그 이름만 쓴다
- 어려운 용어는 **한 답변에서 처음 한 번만** 괄호로 6~10자 설명. 두 번째부터는 용어만. 사용자가 먼저 쓴 용어는 설명하지 않는다
- 쉽게 쓰되 **길이를 늘리지 않는다.** 쉬운 설명을 덧붙이지 말고 어려운 문장 자체를 바꿔 쓴다

> 판단 기준·예시·점검 목록: `~/.dotfiles/claude/docs/wording.md`

## 출력 길이

- 결론 먼저. 작업을 마친 뒤 첫 문장은 "무엇이 됐는가 / 무엇을 찾았는가" 에 답할 것
- 디스크에 쓰는 문서는 필요한 만큼만. 빈 섹션·중복 요약·보일러플레이트로 채우지 말 것

## 환경
- macOS 사용자 대상
- Homebrew, XDG Base Directory 사용 가정
- Shell: zsh (oh-my-zsh)

## 핵심 원칙

- **단순함 우선**: 모든 변경은 최대한 단순하게. 건드리는 코드는 최소화.
- **게으름 금지**: 근본 원인을 찾을 것. 임시방편 없음. 시니어 개발자 기준으로.
- **최소 영향**: 꼭 필요한 부분만 수정. 새로운 버그를 만들지 말 것.
- 코딩 스타일: `~/.dotfiles/claude/rules/coding-style.md` (코드를 쓰기 전에 읽을 것)
