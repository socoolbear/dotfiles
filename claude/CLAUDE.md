# Claude Code Global Settings

> 공용 규칙 (언어·용어·출력 길이·환경·핵심 원칙) 은 아래 import 로 들어오는 `AGENTS.md` 에 있다 (Codex 와 공유). 이 파일에는 Claude Code 전용 규칙만 둔다.

@AGENTS.md

## 도구 기본값
- 파일 읽기는 Read, 검색은 Bash 의 `rg` · `grep` · `find` (2.1.295 기준 Grep · Glob 도구는 없고 셸 명령이 그 역할을 한다).
- **의존성 없는 도구 호출은 한 메시지에 묶어 병렬 실행.** 앞 결과가 다음 호출의 인자를 정할 때만 순차.
- **브라우저 작업은 aside (`mcp__aside__exec` / `mcp__aside__repl`) 를 쓴다.**

## 워크플로우 (요약)

| # | 룰 (한 줄) | 트리거 시 참조 |
|---|---|---|
| 1 | 방향이 갈리거나 구조적 결정 · 되돌리기 어려운 작업은 계획 모드로 시작 | `@docs/workflow.md` |
| 2 | **규모가 큰 계획** (구조적 결정 · 되돌리기 어려움) 은 적대적 검증을 거친 뒤 제출 | `@docs/workflow.md` |
| 3 | **구현은 메인 루프가 직접 한다** (팀 모드 무관). 서브에이전트는 새 컨텍스트가 실제로 필요할 때만 쓴다 — 파일이 겹치지 않는 독립 작업의 병렬 처리 · 대량의 기계적 반복 · 출력이 긴 테스트·빌드 · 넓은 범위 조사 · 별도 시점의 검증. **해당 작업을 다루는 프로젝트 전용 에이전트가 있으면 그쪽을 우선하고 `impl-dev`/`qa-runner` 는 폴백으로만 쓴다.** 병렬은 한 메시지에 도구 호출을 묶는 것이 기본이고, 서브에이전트가 여럿 필요하면 동시 스폰한다 (축끼리 중간에 질문·재지시가 오가야 하면 팀 — 규칙 8). **스폰에 사용자 승인은 받지 않는다** — 위 조건에 맞으면 바로 띄우고 사실만 보고한다 | `@docs/workflow.md` |
| 4 | 사용자 피드백은 auto-memory 가 아닌 **repo 파일** 에 기록. 스스로 알아챈 실수는 auto-memory `발생:` 줄로 시작 | `@docs/feedback-loop.md` |
| 5 | 작동을 증명하기 전 완료 표시 금지 | `@docs/workflow.md` |
| 6 | 사소하지 않은 변경은 "더 우아한 방법?" 자문 후 진행 | `@docs/workflow.md` |
| 7 | 버그 리포트는 자율적으로 끝까지 수정 | `@docs/workflow.md` |
| 8 | **팀메이트를 띄우기 전** 편성 기준을 확인하고, 작업이 끝나면 즉시 해산 | `@docs/team-mode.md` |
| 9 | **사용자에게 물을 것 (확인·결정·요청·제안·승인) 은 착수 전에 모아 `AskUserQuestion` 으로 한 번에**, 선택지마다 선례 조사 결과와 추천안을 붙인다. 작업 중 생긴 질문도 무관한 작업을 먼저 끝낸 뒤 모아서 묻는다 | `@docs/workflow.md` §7 |
