# 교훈 (전역)

> 도구·워크플로우 전반에 걸친 교훈을 쌓는 곳. 라우팅 기준은 `@docs/feedback-loop.md` 참조.
> 특정 프로젝트에만 해당하는 교훈은 여기가 아니라 그 프로젝트의 `docs/lessons.md` 에 쓴다.

## 쓰는 법

- **한 항목에 하나의 교훈.** 제목 한 줄 + 이유 + 다음에 어떻게 할지.
- **왜 그랬는지를 반드시 남긴다.** 결론만 남기면 상황이 달라졌을 때 판단할 수 없다.
- 잘못된 것으로 드러나면 **지운다.** 틀린 교훈은 없는 것만 못하다. 재발이 없다는 이유로는 지우지 않는다 (잘 지켜지는 교훈일 수 있다).
- 저장소·git 이력·`CLAUDE.md`·`AGENTS.md` 가 이미 기록하는 것은 쓰지 않는다.
- 같은 주제가 이미 있으면 새로 만들지 말고 그 항목에 `재발` 날짜를 더한다.

## 형식

```markdown
### <한 줄 제목>  (YYYY-MM-DD)
- **상황**: 무엇을 하다가 나왔는가
- **왜**: 왜 그게 문제였는가 / 왜 그 방법이 맞는가
- **다음엔**: 구체적으로 무엇을 다르게 할 것인가
- **재발**: YYYY-MM-DD <근거>   <!-- 재발 시만 -->
```

### 2026-11-05 — "결정" 항목을 진행 지시로 넓혀 구현까지 하지 않는다
- **일어난 일**: "예외 코드를 지울지 정합니다" 항목에 진행 지시를 받고 삭제 코드·Draft PR 까지 만들었다. 사용자는 그 삭제가 아직 지시하지 않은 다른 항목에 달린 일이라고 지적했다
- **왜**: 사용자가 항목별로 진행·보류를 나눴는데, 결정 항목을 실행으로 넓히면 보류한 항목을 앞질러 간다
- **다음엔**: 지시받은 항목이 "결정·판단" 이면 근거와 추천까지만 내고, 코드·PR·운영 변경은 다시 지시받은 뒤 한다. 다른 항목의 결과에 달린 작업이면 착수 전에 묻는다

### 2026-11-10 — 긴 도구 작업 뒤 최종 보고를 영어로 쓰지 않는다
- **일어난 일**: 한 세션에서 최종 보고를 영어로 써 "한국어로 말해줘" 지적을 세 번 받았다. 셋 다 영어 문서·로그·도구 출력을 오래 읽은 뒤의 보고였다
- **왜**: 응답 언어 규칙 (AGENTS.md "한국어로 응답") 은 있었지만, 직전 맥락이 영어로 가득하면 보고 언어가 그쪽으로 끌려갔다. 같은 지적이 반복되면 사용자가 내용보다 언어를 바로잡는 데 시간을 쓴다
- **다음엔**: 사용자에게 보내는 글을 쓰기 직전에 첫 문장이 한국어 존댓말인지 확인한다. 도구 출력·문서가 영어여도 보고는 한국어로 쓴다
